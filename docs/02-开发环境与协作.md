# 开发环境与协作

## 安装与隔离

使用标准 CPython 3.13 x64，已测 3.13.9，Git 从 [官网](https://git-scm.com/) 获取。运行软件 ZIP 不需要开发工具。

    git clone https://github.com/finalymadeout7433-gif/StudyReview.git
    cd StudyReview
    py -3.13 -m venv .venv
    .\.venv\Scripts\python.exe -m pip install -r requirements.txt

基础网站、桌面与构建分别锁在 requirements.txt、requirements-desktop.txt、requirements/build-windows.txt。无需 React、Node、Torch、CUDA 或 AutoDL。Linux mysqlclient 源码安装需要编译器、pkg-config 和 MySQL/MariaDB 头文件；其他平台以实际验证为准。

私有配置和数据在 checkout 之外，每人新建开发目录；用自己的本机管理员创建全新具名合成库：

    $env:STUDY_DATA_DIR=Join-Path $env:LOCALAPPDATA 'StudyReview\dev-my-branch'
    .\.venv\Scripts\python.exe scripts\prepare_development.py --data-dir $env:STUDY_DATA_DIR --credentials-file '自己的私有 JSON 完整路径' --confirm-create-isolated-schemas
    $env:STUDY_ALLOW_SCHEMA_ADMIN='1'
    .\.venv\Scripts\python.exe manage.py migrate --settings=config.v2_development_settings
    .\.venv\Scripts\python.exe manage.py seed_demo --settings=config.v2_development_settings
    .\.venv\Scripts\python.exe manage.py test learning attachments assistant scheduling ai_gateway --settings=config.v2_integrated_test_settings --keepdb --noinput

prepare_development 只建 study_review_v2_dev_… 与 test_study_review_v2_… 两个新库，不创建用户或 GRANT，不覆盖。已准备的环境直接复用，不反复初始化。测试绝不用当前学习库。

开发 profile 临时用管理员对精确白名单做 DDL/清理，日常 config.settings 用应用身份。完成后移除本次环境变量；不把维护 profile 用于日常软件。

## 运行与构建

    .\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000 --settings=config.v2_development_settings

桌面先装 requirements-desktop.txt，再：

    .\.venv\Scripts\python.exe manage.py collectstatic --settings=config.asset_build_settings --noinput
    .\.venv\Scripts\python.exe -m desktop.main --settings=config.v2_development_settings --data-dir $env:STUDY_DATA_DIR --credentials-file '自己的私有 JSON 完整路径'

独立窗口强制 DEBUG=False，WhiteNoise 只服务收集资源；runserver 是开发工具，不公开部署。

构建先安装 requirements/build-windows.txt，collectstatic 后执行：

    .\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean desktop\StudyReview.spec

完整 dist/StudyReview 放发行目录 Windows程序，配合通用入口、文档和许可。Git 不跟踪大二进制，软件/源码 ZIP 放 Release。

## 分支和 PR

    git switch -c feat/task-search
    git add <明确修改的源码与文档>
    git commit -m "改善任务搜索"
    git push -u origin feat/task-search

每个成员使用自己的本机数据库、配置和演示数据；真实聊天/图片/Key不共享到 Git。所有者核实成员 GitHub 用户名后邀请，公开仓库不自动赋写权限。

PR说明具体触发场景、改后行为、测试与限制。数据库变更一起提交迁移、兼容/回退和测试；不force push main，不靠直接改真库实现需求。避免同时写同编号迁移，冲突先审查依赖，不删历史/表来解决。

必须保留用户隔离、归档只读、历史不可变、幂等、版本签名和预算约束。提交前跑秘密检查、适用测试、git diff --check。误提交秘密先撤销对应凭据再处理历史，工作区删除不等于旧提交已删除。
