# 开发预览异常退出后的启动恢复

2026-10-28遇到启动器报“Existing development state is not healthy”。核对发现运行记录对应PID已经不存在、8001无监听，而独立开发MySQL仍正常。原启动器遇到任何旧状态一律拒绝启动，因此未能自行恢复。

现在启动器在健康检查失败且有旧状态时，调用desktop.development_state：验证独立开发配置、禁止链接路径、取得原有操作系统实例锁，确认记录的进程已结束且端口可独占绑定，然后将状态原样改名备份在同一个private目录。正常启动继续走原流程。活进程、锁占用、端口占用、未知或变化的状态均拒绝自动恢复。

没有结束任何进程，不读取API密钥、不重置数据库或预算、不删除锁文件。仅恢复独立开发环境；旧EXE和原版数据库不受影响。Windows空闲端口使用独占绑定验证，避免连接空端口时的超时误判。

六项回归覆盖失效状态备份、重复恢复、活PID和占用端口、持有中的锁、损坏/外来状态、原版配置拒绝，以及真实当前PID和监听端口的检查。已实际用本机失效状态验证恢复启动。
