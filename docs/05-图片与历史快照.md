# 图片与历史快照

入口为 attachments/models.py、services.py、views.py；历史保护在 migrations/0002_immutable_image_guards.py。

## 输入和规范化

已登录用户可选择/粘贴PNG/JPEG/WebP，检查真实解码而不只信扩展名/MIME。输入最多8MiB、20,000,000像素、单边10,000；静态图像规范化为去元数据PNG并生成缩略图。每用户额度500MiB；聊天一次最多4图、总8MiB。不是任意PDF/附件系统。

保留图像内容，不保证原文件字节、EXIF/定位元数据。不得绕开大小/像素检查直接保存。

## 私有存储和授权

Attachment保存owner、UUID、storage_key、sha256、尺寸及字节数，owner+sha256去重；不同用户不能凭相同哈希取他人图像。字节放数据目录private/media，不塞数据库BLOB，不使用用户文件名作路径。

原图与缩略图经 /attachments/<uuid>/ 与 thumbnail/ 按用户授权，不能经WhiteNoise/static直接公开。路径限定私有根，拒绝symlink/Windowsjunction等重解析点；真实junction测试在新的系统临时目录核对目标未被删除，不对真实媒体目录操作。

## 当前和历史

QuestionImage按题干、原答、参考答案、错因区分用途与顺序，只关联本人图片。复习形成ReviewImageManifest和ReviewImageSnapshot，冻结当时关系、名称/尺寸/哈希，零图也保存清单；后续改题/加图不会改旧历史。

ReviewRecord同时保存文本快照，图文与复习流程同存。Attachment/Manifest/Snapshot禁止普通ORM/SQL更新删除，高权限DDL不在保证内；归档不删除历史。

数据库事务不能自动回滚文件，服务有临时文件及故障清理；改文件逻辑要看故障注入测试。备份SQL与media/缩略图必须同一时点并核对清单；只备份SQL会留下打不开的历史图像。真实图像/截图不入Git。
