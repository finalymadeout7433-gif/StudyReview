# 智能复习调度模块

本应用只新增 `SchedulingState` 与 `ScheduleEvent` 两张业务表，不修改原 `ReviewRecord` 历史字段。未发生下一次真实复习时，既有 `WrongQuestion.next_review_date` 和旧历史保持不变；读取建议不会创建状态。新复习才冷启动 FSRS，不将旧“不熟/掌握”标签当成准确的算法训练资料重放。

## 固定依赖与配置

- 官方 `fsrs==6.3.2`，MIT；核心仅依赖 `typing-extensions`，未使用 optimizer/Torch、远程服务或个人参数训练。
- `desired_retention=0.9`、`learning_steps=()`、`relearning_steps=()`、`enable_fuzzing=False`；使用该固定版默认的 21 个参数，完整参数与配置写入状态和每次调度事件。
- 算法版本 `6.3.2`，应用配置版本 `shanghai-daily-v1`。版本、状态或 JSON 损坏时明确失败并保留原数据，不自动清零，也不默默切回旧算法。
- `again` = 未能独立答对，或看答案后才会；`hard` = 独立答对但回忆费力；`good` = 独立正确作答。不映射 Easy。旧历史的显示文案及原语义由主项目保留。
- 算法精确到期时间使用 UTC。日级建议明确转换为 Asia/Shanghai，至少为本次复习当地日期的下一天；人工改期独立保存建议、实际日期及 override，不覆盖精确算法到期值。
- 首次复习的固定版默认结果为 Again 1 天、Hard 1 天、Good 2 天。日级取整可能相同，不能承诺三档严格递增；Good 仍需要后续复习。90% 是算法目标配置，不是记忆效果保证。

## 集成接口

```python
from scheduling.services import (
    suggest_schedule, prepare_schedule, commit_schedule, schedule_revision,
)
```

`suggest_schedule(user, question, rating, reviewed_at=None)` 返回只读 `ScheduleProposal`，含 `due_date`、`due_utc`、`explanation`、`cold_start`、版本及前后快照。预览不能提交；保存时重新计算。

`prepare_schedule(user, question, rating, reviewed_at)` 要求调用者已经进入事务并依次锁定 course、question；本服务最后锁定 state。用户与题目采用唯一约束；第一次状态使用稳定 `card_id=question.pk` 创建，后续使用修订号防旧页面覆盖。调用者签名版本应包括 `schedule_revision(user, question)`。

`commit_schedule(proposal, review_record, user_override_date=None)` 要求同一事务内已保存与 proposal 匹配的 `ReviewRecord`。核对归属、归档、题目、评分、时间、日期、修订号与重新计算结果，再写不可变事件并更新 state；同一 record 的同一提交再次调用会返回已有事件，不重复前进。

调用者必须使用**同一个** `reviewed_at` 写入 `ReviewRecord.reviewed_at` 并传给 prepare；其 `review_date` 为该时间的 Shanghai 日期，`next_review_date` 为实际建议或用户选择。最后更新 `question.next_review_date`，仍处于同一根事务。失败应从根事务抛出，使复习历史、状态、事件和题目日期一同回滚。本模块不自行修改 question 的日期。

## 数据保护与迁移

两表的外键采用 PROTECT；事件与原复习记录为 OneToOne。状态唯一约束、事件日期与修订号 CHECK、事件索引均由迁移建立。`0002_event_guards` 仅对新 `scheduling_scheduleevent` 安装禁止普通 UPDATE/DELETE 的 MySQL 触发器，不修改旧触发器；迁移使用已授权的迁移连接，不读取凭据或建立新长期访问。MySQL 迁移只允许 `settings.AUTHORIZED_MIGRATION_SCHEMAS` 精确列出的库，并要求 `STUDY_ALLOW_SCHEMA_ADMIN=1`。

`0003_override_null_guard` 明确禁止 SQL NULL 分支绕过“人工改期必须留痕”的 CHECK。ORM 同样拒绝事件更新、删除、批量更新。用户权限及归档规则由应用服务校验，并不声称 MySQL 行级用户权限或高权限账号无法删改。

恢复旧版程序前，应备份包括新表的数据并导出事件；不得以撤销迁移直接丢弃新增历史。旧问题和复习记录表结构未变。数据损坏的修复需明确迁移，不能重新初始化代替修复。



当前新复习使用FSRS，不是初版固定1/3/7天；合成旧历史只是历史示例。本轮测试见[发行验收](12-发行验收记录.md)，测试命令见[测试与CI](08-测试与CI.md)。
