# 账号学习资料包与整库备份

页面入口：侧栏「资料备份」。浏览器提供 ZIP 下载；原生窗口保存到当前数据目录 `private/exports/<用户ID>/`。只导出当前账号，不包含登录密码、认证会话、数据库配置、API 密钥、浏览器状态或系统密钥。

账号资料包涵盖当前版本全部 22 类业务数据：课程、章/节、知识点、任务、错题及知识点关系、复习历史、图片及历史快照、专注会话和有效时段、助手本地会话/消息/建议、复习算法状态/历史、AI 记账元数据。原图与缩略图一并保存。使用一致性只读快照，保留原始主键和微秒级时间。

整库备份是另一种维护方案，需保管所有账号、完整数据库 SQL（结构、外键、触发器和数据）及同一时点媒体；含敏感账号信息。账号资料包不代替整库备份。单项专注 JSON 只用于统计交换。

## 预检

网页上传只进行检查，不执行 SQL、不提取任意路径、不写业务数据。检查格式/迁移/字段清单、22 类业务表覆盖、字段类型、所有权、依赖、唯一关系、课程层级、调度版本、专注时段、文件哈希、原图/缩略图和尺寸；拒绝异常路径、重复 ZIP 项、加密包及超额包。限制：压缩 128 MB、展开 256 MB、50,000 条记录、JSON 32 MB。超限直接拒绝，绝不截断。

结构与校验通过只代表文件可解析且内部一致，不证明可信来源，也不保证目标可恢复。目标还需具备匹配迁移、业务表、全部业务外键及 24 个保护触发器。数据库剩余空间、MySQL 限额等错误仍可能在事务写入时出现。

旧 `studyreview-private-account-v1` SQL 账号包不会直接执行；缺少新版章节与专注等结构的包需要另行设计、测试迁移方案，不静默忽略资料。

## 恢复边界

当前恢复属于维护功能，没有网页导入按钮。只允许显式确认的、准确命名且已授权的隔离开发/测试库；目标已完成当前迁移、仅一个普通空账号、22 类业务表全空且媒体目录为空。已有任何业务数据或其他账号即拒绝，不合并、不清空、不更新旧行。不更改目标登录凭据。

先关闭目标程序。通过源码环境运行：

```text
python manage.py restore_learning_archive --archive <资料包绝对路径> --username <目标已有普通账号> --report <全新报告绝对路径>
```

默认只预检。维护人员在核实确为合成隔离空间后，额外传入 `--expect-database <准确库名> --confirm-empty-workspace` 才会恢复。不要使用真实学习库做演练。MySQL 8.0.16+；原始附件脚本或未知 SQL 不应直接执行。

恢复先完整验证并暂存媒体，再以事务插入已排序的关联记录，保持外键及触发器启用；仅把用户外键映射到目标账号，主键、内容和历史时间保持不变。提交前再次逐字段比较，并校验全部外键。目标正在运行或已有未完成恢复标记时拒绝。

数据库提交与文件系统不能构成同一个原子事务。因此恢复开始即写入 `archive-restore.pending.json`，仅全部成功后移除。发生文件写入、提交或进程崩溃等异常时保留标记及暂存媒体，阻止重试和原生启动；需维护人员核对实际数据库和媒体后处理，不能假设失败就可再次导入，也不能只删除标记。工具不自动删除或覆盖这些文件。

正在运行的专注不允许导出，先暂停或结束，避免恢复后虚增学习时长。有机器绑定密钥的 AI 配置可归档但阻止恢复，不擅自清除配置；密钥迁移没有实现。待确认助手建议保留原文，跨环境确认签名不保证可用，应重新生成预览。

本轮验收范围是同一电脑上的独立 MySQL 库和合成账号；不等于另一台电脑、新 MySQL 实例或旧账号包迁移已验收。整库 SQL 恢复仍走单独维护流程。
